# 제품 콘셉트
제목: **수상한 영수증**

플레이어는 한빛지방국세청 특별조사2계 조사관이다. 현장 출동, CCTV, 심문 미니게임은 없다. 용의자가 낸 영수증, 지출내역서, 출입기록, 카드 승인로그, 사업자 등록 메모만 책상 위에 놓고 날짜·시각·장소·금액·사업자번호가 서로 싸우는 지점을 집어 보고서를 쓴다.

알리바이는 문장으로는 완벽하다. 모순은 서류 안의 숫자와 지명에만 있다.

인디 책상 느낌: 크림색 종이, 먹색 글자, 인주 빨강, 세무 녹색, 클립 금색. 두꺼운 도장, 절취선, 서류철. 보드게임처럼 원색을 쏟지 마라.

# 화면
1. **표지.** 제목 "수상한 영수증". 부제 "서류만 보고 쓰는 조사". 시작 / 이어하기 / 매뉴얼. 세션이 없으면 이어하기는 비활성.
2. **사건 철.** 폴더 5개. 이름, 한 줄 질문, 난이도, 도장(미착수·조사중·종결).
3. **책상.** 본 플레이.
4. **보고서.** 종결 제출.
5. **매뉴얼.** 언제든 열 수 있는 규칙집. 현실 세법 면책 한 줄.
6. **종결 메모.** 과장 오세린의 짧은 총평. 다음 폴더로 / 철로.

Esc는 열린 종이·매뉴얼·보고서를 닫는다. 책상에서 Esc 한 번 더 또는 "철로"는 사건 선택으로. 진행은 저장되므로 나가도 지적이 사라지지 않는다.

# 책상 조작
데스크톱 우선. 가로 1100px 이상에서 3열.

- 왼쪽: 서류 목록. 필터는 사람 / 날짜 / 종류(영수증·내역서·기록·등록). 검색은 상호·금액·번호 부분 일치.
- 가운데: 연 서류 한 장. 종이 재질. 종류마다 레이아웃만 다르게 (영수증 절취선, 내역서는 표, 로그는 등폭 숫자).
- 오른쪽: 그날의 타임라인. 시각이 있는 서류는 자동으로 올라간다. 누르면 가운데에 연다.
- 하단 대조 슬롯: 서류를 1~3장 핀. 나란히 보고 "지적 올리기". 정답 지적도 전부 3장 이하다.

지적 올리기:
- 핀된 서류 집합 (순서 무관)
- 모순 유형 하나 (매뉴얼과 같은 목록)
- 플레이어 메모 한 줄은 저장만 하고 채점하지 않음

판정 (`logic.js`):
- 서류 id 집합이 정답 지적의 `docIds` 와 같고, 유형이 같으면 인정.
- 집합이 더 크거나 작으면 거절. 멘트는 "이 조합은 모순으로 성립하지 않습니다." 정답 유형이나 정답 서류를 알려주지 마라.
- 이미 인정한 지적의 재제출은 "이미 보고서에 있습니다."
- 인정 시 인주 도장 애니메이션과 짧은 도장 소리. 과장 설명 `why` 는 인정 후에만 보여 준다.

키보드:
- `J` / `K` 목록 이동, `Enter` 열기, `C` 대조에 핀, `F` 지적 올리기, `M` 매뉴얼, `R` 보고서, `Esc` 닫기
- 보이는 버튼과 같은 동작. 포커스 링 유지.

# 보고서
- 인정된 지적만 첨부할 수 있다.
- 대상 인물 하나, 위반 유형 하나, 지적 전부 첨부.
- 정답 조건: `personId`, `crimeId`, 그리고 `requiredFindingIds` 가 모두 인정·첨부.
- 틀리면 오세린이 한 줄만 돌려준다. 누구인지, 어떤 유형이 맞는지는 말하지 마라.
  - 인물이 틀림: "사람부터 다시 보십시오."
  - 위반 유형이 틀림: "위반 이름을 서류에 맞게 고르십시오."
  - 지적이 부족: "근거가 모자랍니다."
- 거절 2회: 힌트 1. 해당 사건 `hints[0]`. 볼 서류의 윤곽만 말한다.
- 거절 4회: 힌트 2. `hints[1]`. 필요한 모순 유형 이름을 말한다. 어느 서류인지는 말하지 않는다.
- 오답으로 사건을 잠그지 마라. 언제든 재제출.

종결 후 그 사건 서류는 읽기 전용으로 다시 펼칠 수 있다.

# 조사 매뉴얼 (게임 규칙 전문)
매뉴얼에 이 표를 그대로 보여 줘라. 매뉴얼 밖에 숨은 공식으로 풀리게 하지 마라.

이동 최소시간 (같은 사람의 카드 또는 출입이 이 시간보다 짧게 두 도시를 밟으면 동선 모순):

| 구간 | 최소 |
| --- | --- |
| 한빛시 중구 본사 ↔ 남해휴게소 | 70분 |
| 한빛시 중구 본사 ↔ 남해항 | 90분 |
| 한빛시 ↔ 북원시 | 150분 |
| 한빛시 중구 ↔ 한빛시 강남구 | 40분 |
| 같은 건물 안 | 0분 |

규칙:
- 출입기록의 IN 시각부터 OUT 시각까지는 그 건물 안으로 주장된 구간이다. 그 구간에 다른 도시 결제가 있으면 동선 모순.
- 같은 단말기에서 영수증 번호는 시간순으로만 증가한다. 더 큰 번호가 더 이른 시각이면, 그 사이 번호의 시각 변조다.
- 지출내역서의 계정·품목 문장과 같은 날·같은 금액·같은 상호의 영수증 품목이 다르면 계정 위장.
- 한 달 사적 카드 합계가 그 달 실수령의 3배를 넘으면 자금출처 조사 대상이다. 급여명세서에 "다른 소득 없음"이 있고 입금 전표가 있으면, 그 입금처가 출처다.
- 종이 영수증의 번호가 다른 가게 영수증과 같거나, 카드사 로그에 그 시각의 실시간 승인이 없거나, 사업자 상태가 폐업이면 위조 영수증.
- 회식 영수증의 기재 인원이 메인 메뉴 수량의 2배를 넘으면 허위 인원. 1인 상한은 80,000원 (상한 초과만으로 범인을 지목하지는 못한다. 인원 허위와 함께 볼 것).
- 영수증 상호와 사업자등록 메모의 상호·업태가 다르고 등록번호가 같으면 위장 사업자.
- 서로 다른 사건의 결재자 이름이 같은 사람인지 대조하는 것은 결재 연결.
- 사업자등록번호가 사건 둘 이상에서 같으면 조직 연결.

모순 유형 선택지 (전체 사건 공통, 사건마다 쓰이지 않는 유형이 있어도 목록은 유지):
동선모순, 시각변조, 계정위장, 자금출처, 위조영수증, 허위인원, 위장사업자, 결재연결, 조직연결

# 데이터 스키마
각 사건 파일은 이 형태만 쓴다.

```js
{
  id: "case01",
  title: "",
  question: "",          // 폴더에 보이는 한 줄
  difficulty: "입문",
  briefing: "",          // 오세린이 주는 지시. 범인을 지목하지 마라
  people: [{ id, name, role, suspect: true }],
  crimes: [{ id, label }],   // 정답 1개 + 오답 선택지
  docs: [{
    id, kind, title, personId, date, time, placeId,
    fields: [{ label, value }],   // 화면에 찍히는 전부
    // structured 값은 fields에 이미 보이는 값만 담는다. 화면에 없는 숫자로 판정하지 마라.
    structured: {}
  }],
  findings: [{
    id, type, docIds: ["a", "b"], why: ""
  }],
  accusation: {
    personId, crimeId, requiredFindingIds: [],
    entityId: null   // 사건 5만 사업자 번호 문자열
  },
  hints: ["", ""],
  epilogue: ""
}
```

`type` 은 모순 유형 문자열과 정확히 일치. `logic.js` 는 사건 데이터를 받아 `submitFinding(caseData, docIds, type)` 와 `submitReport(caseData, { personId, crimeId, findingIds, entityId })` 를 제공한다. `entityId` 는 사건 5에서만 검사한다. 부작용 없이 `{ ok, reason }` 을 돌려라.

인물 id (모든 사건에서 고정): `park` 박도윤, `choi` 최민재, `han` 한서준, `bae` 배수아, `yoon` 윤가람, `kim` 김하늘, `oh` 오세린. 오세린은 용의자가 아니다.

## 사건 1. 야근 도시락 (입문)
질문: 박도윤의 3월 14일 야근은 사실인가.

브리핑: 한빛물산 총무 대리 박도윤이 야근식대 8,500원을 청구했다. 진술과 출입기록은 깔끔하다. 가맹점 대조 전표와 카드 사용분만 확인해 보고서를 쓰라.

인물: 박도윤 (용의자, 총무 대리).

위반 선택지: `false-ot` 허위 야근, `embezzle` 횡령, `slush` 비자금 수수.
정답 인물 박도윤, 정답 위반 `false-ot`.

서류:
- `stmt` 진술. 박도윤. "2026-03-14 21:00부터 03-15 01:00까지 한빛시 중구 본사에서 야근. 22:14 본사 1층 별빛마트에서 도시락."
- `gate` 출입기록. 본사 게이트 IN 21:05, OUT 03-15 01:12. 그 사이 기록 없음.
- `exp` 지출내역서 한 줄. 2026-03-14 22:14, 계정 야근식대, 상호 별빛마트 본사점, 8,500원, 카드 끝자리 3812, 영수증번호 4820.
- `mart` 영수증. 별빛마트 본사점, 한빛시 중구 청사로 12, 사업자 120-33-10021, 단말기 T-04, 번호 4820, 시각 22:14, 도시락 8,500, 카드 3812.
- `seq` 가맹점 대조 전표 (단말기 T-04). 세 줄만.
  - 4819 / 21:02 / 생수 1,200
  - 4820 / 금액 8,500 / 시각 칸 공란 (가맹점 보관본)
  - 4821 / 21:40 / 김밥 3,200
- `rest` 영수증. 남해휴게소 상행, 22:47, 아메리카노 4,500, 카드 3812, 단말기 H-19.
- `fish` 영수증. 부두횟집, 남해항 부두길 4, 23:28, 모둠회 2인 86,000, 카드 3812. 하단 손글씨 메모 "청람 건". 이 메모는 사건 1 정답에 필요 없다. 지우지 마라.
- `park` 영수증. 남해항 공영주차장, 23:41, 2,000, 카드 3812.

필수 지적:
1. `f-time` 시각변조. 서류 `mart` + `seq`. 4821이 21:40인데 제출본 4820은 22:14다.
   why: "번호는 시간순입니다. 4820은 21:02와 21:40 사이여야 합니다. 22:14는 나중에 쓴 시각입니다."
2. `f-route` 동선모순. 서류 `gate` + `rest`. IN 21:05부터 OUT 01:12까지 본사 안으로 주장되는데 22:47 남해휴게소 결제가 있다.
   why: "게이트는 그 시각에 그를 본사 안에 둡니다. 카드는 남해휴게소에 둡니다."

힌트:
1. "별빛마트 단말기 번호와, 본사에 남아 있다던 시각의 카드 한 장을 나란히 보시오."

## 사건 5. 청람의 꼬리 (최종)
해금: 1~4 종결.

질문: 네 사건을 관통하는 창구는 누구와 어느 사업자인가.

브리핑: 오세린. "새 심문은 없습니다. 이미 인정한 서류와 오늘 도착한 출금 메모만 다시 펴십시오. 보고서에는 내부 결재자와 사업자, 둘을 적으십시오."

이 사건만 보고서 필드가 둘이다.
- 내부 창구 인물
- 사업자 (선택지: 청람유통 814-22-01937, 별빛마트 120-33-10021, 루프44 505-10-22008)
- 위반 유형은 `org` 조직 비자금 하나만 두고, 오답으로 `false-ot`, `fake-exp` 를 남겨라.
정답: 인물 `yoon`, 사업자 `814-22-01937`, 위반 `org`. `submitReport` 는 이 사건에서 `entityId` 가 다르면 `{ ok: false, reason: "entity" }` 를 준다. 화면 멘트는 "사업자부터 다시 보십시오."

책상에는 이전 사건의 서류를 복사해 다시 보여 준다. 복사본 id는 `p2-exp`, `p2-ins`, `p3-roof`, `p4-dinner`, `p4-reg`, `p1-fish`. 원본 사건 저장은 건드리지 마라. 사건 5 데이터 안에 그 서류의 필드(금액, 번호, 결재자, 메모)를 다시 적어라. 플레이어가 이전 사건을 외워야만 풀리게 하지 마라.

추가 서류 `flow` 출금 메모 (청람유통 814-22-01937):
- 03-01 최민재 상담료 6,000,000
- 03-08 최민재 상담료 6,000,000
- 03-15 최민재 상담료 6,000,000
- 03-11 가맹 매출 4,200,000 적요 금강루 (같은 번호의 자기 거래)
- 03-14 현금 2,000,000 적요 "항만 상담" 수령 이니셜 ㅂㄷㅇ

필수 지적:
1. `f-org` 조직연결. `p2-ins` + `p4-reg` + `flow`. 입금, 등록, 출금 메모의 번호가 모두 814-22-01937.
   why: "상담료와 회식 간판과 출금이 한 번호입니다."
2. `f-sign` 결재연결. `p2-exp` + `p3-roof` + `p4-dinner`. 토너 줄, 루프44, 금강루의 결재자가 모두 윤가람.
   why: "쓰는 사람은 달라도 결재란은 같은 사람입니다."
3. `f-port` 조직연결. `p1-fish` + `flow`. 부두횟집 메모 "청람 건" 과 03-14 항만 상담 현금, 이니셜 ㅂㄷㅇ.
   why: "야근이 아니던 밤과 청람의 항만 현금이 같은 날짜입니다. 이니셜은 박도윤으로 남기되, 최종 창구로 올리지는 마십시오."

`f-port` 는 필수 지적에 포함하되, 보고서 대상 인물을 박도윤으로 고르면 틀린 것으로 하라. 정답 인물은 윤가람이다.

힌트:
1. "같은 등록번호가 찍힌 종이 세 장, 그리고 결재란에 반복되는 이름."
2. "조직연결 둘, 결재연결 하나입니다. 사람은 결재란입니다."

에필로그: "창구는 윤가람, 주머니는 청람유통입니다. 슈퍼카 부품도, 열여덟 명의 저녁도, 남해항 메모도 그 꼬리입니다. 오늘 보고서는 여기까지입니다."

사건 5를 풀었다고 폭력 장면이나 검거 연출을 넣지 마라. 도장 "종결" 과 철로 돌아가면 다섯 폴더에 종결 도장.

# 시각
- 배경은 어두운 책상(#2a241c). 종이 #efe6d4, 잉크 #1c1915, 인주 #8f1d1d, 세무 녹색 #1f4d3a, 클립 #b0893e.
- 영수증은 너비 고정, 점선 절취, 약한 회전은 목록 썸네일에만 (±1.5도). 본문은 수평으로 읽어라.
- 인정된 지적에는 "인정" 도장. 종결 폴더에는 "종결".
- 숫자·사업자번호·카드 끝자리는 등폭 (`ui-monospace, monospace`).
- 흔들림, 번쩍임 남용 금지. 도장은 한 번만.
- 대비는 본문 기준으로 충분히. 종이는 밝게, 글자는 거의 검정.

- `node SuspiciousReceipts/js/logic.test.js` 가 종료코드 0. 테스트는 DOM 없이 `logic.js` 만 불러 다음을 확인한다.
  - 각 사건 정답 지적이 모두 인정된다.
  - 서류를 하나 더하거나 빼면 거절된다.
  - 유형만 바꾸면 거절된다.
  - 정답 보고서가 통과한다.
  - 인물만 바꾼 보고서, 유형만 바꾼 보고서, 지적 하나 뺀 보고서는 거절된다.
  - 사건 2의 금강루 일치 쌍은 거절된다.
  - 사건 1에서 `rest`+`fish` 는 거절된다.
- 새로고침 후에도 인정된 지적과 종결이 남는다.
- 다섯 사건을 매뉴얼만 보고 종결할 수 있다. 정답 서류에만 있고 화면 필드에 없는 값은 없어야 한다.
- 주석은 한국어로 핵심만.
- 완성 후 브라우저에서 표지 → 매뉴얼 → 사건 1을 일부러 틀린 지적 한 번 → 정답 종결 → 사건 2·3·4 종결 → 사건 5 해금과 종결 → 새로고침 복원 → 초기화까지 직접 눌러 확인하라. 스크린샷만 찍고 끝내지 마라.
