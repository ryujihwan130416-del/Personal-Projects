당신은 프론트엔드 게임 개발자다. 이미 완성된 `PartyArchive/` (로컬 HTML 2인 파티 미니게임 모음)를 **처음부터 만들지 말고**, 기존 코드를 읽고 개선·확장하라.

# 현재 상태 (건들지 말고 유지할 것)
- 경로: `PartyArchive/`
- 기술: HTML + CSS + Vanilla JS만. npm/프레임워크/번들러/CDN/외부 이미지·mp3 금지. `file://`에서 동작해야 함.
- UI 전부 한국어. 닌텐도/마리오 IP 금지.
- 기존 구조 유지: `index.html`, `styles/{base,lobby,games}.css`, `js/{app,ai,input}.js`, `js/games/{tug,draw,potato,stopbar,moles}.js`
- 기존 5게임(줄다리기/눈치/폭탄/타이밍스톱/두더지)과 PvP·vs AI·난이도·세션 점수·뮤트는 유지.
- `PROMPT.md`는 원문 보존. 이번 작업용 프롬프트는 `UPDATE_PROMPT.md`로 저장.

# 목표
v1을 “플레이 가능한 데모”에서 **파티에서 반복해서 돌리고 싶은 v1.5**로 올려라.
우선순위: (1) 버그/데드락 수정 → (2) 메타 루프 → (3) 연출/사운드 → (4) UX 정리.
범위 밖: 온라인 멀티, 3인+, 계정, 물리엔진, 퀴즈/어드벤처, 새 프레임워크.

# 필수 버그 픽스
1. **stopbar 소프트락**: 한쪽이 안 누르면 라운드가 영원히 안 끝남. N초(예: 6~8초) 타임아웃 후 미정지 플레이어는 0점 처리하고 다음 라운드로.
2. **타이머/리스너 누수**: `moles` 경직 `setTimeout` 등 `destroy()`에서 전부 clear. 각 게임 `destroy` 후 로비 왕복해도 타이머·keydown이 남지 않게.
3. **보조키 정리**: `input.js`의 S/K가 실제로 쓰이지 않음.
   - 권장: 최소 2개 게임에 의미 있는 보조 행동 부여
     - moles: S/K로 열(또는 행) 선택 후 주키로 타격, 또는 가운데 열 전용 쟁탈 키
     - potato: S/K로 잠깐 “움켜쥐기/버티기”(폭발 직전 리스크·보상) 또는 패스 방향 고정
   - 보조키를 안 쓰는 게임은 로비 범례/카드에서 S·K 안내를 빼라. 광고만 하고 안 쓰는 상태 금지.
4. **draw 동시 입력**: 같은 프레임(또는 아주 짧은 윈도우) 동시 누름은 무승부 처리.

# 메타 루프 (로비에 추가)
아래 중 **둘 다** 구현:
1. **랜덤 한 판**: 5게임 중 무작위 1개 즉시 준비 화면.
2. **토너먼트(파티 모드)**: 5게임을 섞은 순서로 연속 플레이. 세션 승수(또는 토너먼트 전용 스코어)로 최종 우승자. 한 판 끝나면 자동으로 다음 게임 준비 화면. 중간에 Esc면 토너먼트 중단·점수 반영 없음(또는 “포기” 확인 후 로비—기존 Esc 규칙과 일관되게).

모드(PvP/AI)·난이도는 `localStorage`에 저장해 다음 방문 시 복원. 점수 키와 네임스페이스 분리 (`partyArchive.prefs.v1` 등).

# 공통 셸 리팩터 (동작 동일, 코드만 정리)
- 각 게임 파일에 복붙된 카운트다운/결과 오버레이를 `js/app.js` 또는 `js/ui.js` 공통 헬퍼로 빼라.
- 카운트다운 끝에 **"시작!"** 한 박자(0.3~0.5초) 추가.
- 결과 화면에서 **Space = 다시하기**, 버튼과 동일 동작.

# 연출 / 사운드 (과하지 않게, 파티감↑)
- Web Audio만 사용. 게임별 짧은 차등 사운드:
  - tug: 연타마다 피치 약간 상승
  - potato: 퓨즈 틱/히스, 폭발 시 강한 펀치
  - moles: 획득 팝, 경직 Dull thud
  - draw: 신호/오신호 톤 구분
  - stopbar: 스톱 시 점수대별 피치
- 비주얼 주스(CSS/DOM):
  - tug 깃발·줄 스트레치
  - potato 투척 아크/착지
  - moles 점수 팝업(+1) 및 획득 플래시
  - 승리 시 짧은 화면 펀치(기존 soft-shake보다 한 단계만 세게, 남용 금지)
- 이모지 남용 금지. CSS 도형 유지.

# 로비 UX
- 첫 뷰포트에 **타이틀 + 모드/난이도 + 게임 그리드**가 빨리 오게 압축. 긴 설명·범례는 접거나 하단으로.
- 마지막 플레이한 게임 카드에 “최근” 표시.
- 토너먼트/랜덤 진입점을 카드 그리드와 같은 시각 계층으로(별도 대시보드 느낌의 카드 더미 남발 금지). 보드/파티 테이블 톤 유지.

# AI 튜닝
- potato: “남은 시간 짧을수록 던질 확률↑”를 실제로 체감되게(매 프레임 순수 랜덤만 쓰지 말고 긴장 곡선).
- moles: 가운데 열 쟁탈에서 쉬움은 늦고, 어려움은 공격적이되 매 프레임 완벽 추적은 금지.
- stopbar 타임아웃 후에도 AI가 멈추지 않는 경우 대비.

# 품질 기준
- 새로고침 없이 로비↔게임↔토너먼트 왕복, `destroy` 누수 없음.
- Esc = 언제든 로비, 진행 중 나가면 해당 판 점수 없음(기존 규칙 유지).
- vs AI에서 P2 키 무시.
- 데스크톱 한 키보드 2인 우선. 모바일은 깨지지 않을 정도만(터치 풀지원은 선택).
- 60fps 목표. `requestAnimationFrame` 유지.
- 수동 스모크: 로비 → 5게임 각 1회 완주 → Esc 중도 퇴장 → 랜덤 → 토너먼트 2판 이상 → 뮤트/점수 초기화/새로고침 후 prefs 복원.
